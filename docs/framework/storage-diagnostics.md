# Read-only browser storage diagnostics

`SCOS.storageDiagnostics.inspect(ownerSignal?)` queries the browser on explicit demand. It returns immutable, independent `estimate` and `persistence` outcomes: `observed`, `unsupported`, `denied` (this query was refused), or `failed`. The client exposes no mutation, persistence request, permission request or storage-manager object. Retain the existing Application → Window → ViewController ownership and pass the controller/task signal for a narrower lifetime. The mounted client also rejects after window/mount/runtime or account retirement; cancellation does not cancel the underlying browser promise.

An observed estimate contains `usageBytes` and `quotaBytes`, with `null` for an omitted field and `approximate: true`. Zero is a real observation, never a substitute for unsupported/error. These are coarse origin-level estimates; they are not a per-account/document breakdown or device free-disk measurement. No `usageDetails`, error messages, URLs or account identifiers are projected. The independent current `persisted` boolean is not a permission verdict, backup, offline-availability guarantee or update-readiness evidence. Browser write failures still require ordinary document/persistence recovery.

System Preferences → Storage uses the same reader through the host runtime. Its NSEObject presentation controller owns explicit check/refresh generations, cancels superseded requests, clears observations on account/runtime/dialog retirement and disposes its existing-service subscriptions on unmount. Opening the pane or its summary makes no query. There is no polling or browser-global listener. A reopened pane requires a fresh check. Host storage diagnostics do not close the readiness inventory's persistence-work, schema-compatibility or offline-rollout gaps.

The [Storage Standard](https://storage.spec.whatwg.org/#api) distinguishes status queries from the mutating persistence request. Browser estimates may be imprecise or unavailable. Runtime feature detection and caught outcomes, rather than a fixed browser-version promise, define support. The Storage pane supplies only the status queries; installation, service workers, caching, persistence requests and updates remain separately gated.
