## Date formatter

`NSEDateFormatter` is an `NSEFormatter<Date>` with mutable `locale`, `timeZone`, `calendar`, `dateStyle`, `timeStyle` and `dateFormat`, `string` and `date`, plus the existing formatter protocol methods. Locale, zone and calendar formatting use `Intl.DateTimeFormat`; locale digits use `Intl.NumberFormat`. Styles format through Intl, and style parsing tokenizes Intl parts for numeric fields, localized month names and day periods, then validates weekday, era and zone text by formatting the resulting instant. Time-only parsing uses 2001-01-01. Invalid dates and daylight-saving gaps return null. Repeated wall times resolve to one matching instant; no disambiguation control is provided. Style parsing uses 2000–2099 for two-digit years and therefore cannot round-trip short-style dates outside that range. Whitespace variants emitted by Intl format/parts are accepted.

Parsing supports the Gregorian calendar only, including locale-selected calendars; other calendars throw rather than silently interpreting their fields. Style formatting supports Intl calendars, but unsupported Intl parsing parts throw. Explicit `dateFormat` supports only `yyyy`, `MM`, `dd`, `HH`, `mm`, `ss`, punctuation, quoted literals and doubled apostrophes; unsupported pattern letters throw. Explicit patterns support Gregorian AD years 0001–9999; unsupported eras and calendars throw. Fields omitted from a pattern default to 2001-01-01 00:00:00. Parsing is strict and millisecond-free. Partial-string validation is permissive. This is a bounded JavaScript bridge, not an ICU/Unicode date-pattern implementation.

## Decimal number

`NSEDecimalNumber` is an immutable base-ten value bounded to 38 significant digits and a decimal exponent from -128 through 127. It supports `fromString`, `zero`, `one`, `notANumber`, addition, subtraction, multiplication, division, comparison, `rounding`, and decimal string/JSON output. Decimal strings accept signs, optional leading or trailing zero around the decimal point, and scientific notation. It does not provide binary floating-point conversion or every Foundation arithmetic selector.

`NSEDecimalNumberHandler` implements the structural `NSEDecimalNumberBehaviors` contract. A handler selects `plain`, `down`, `up` or `bankers` rounding, optional decimal-place scale (-127 through 128), and exception flags. The default omits scale, retains at most 38 significant digits, uses plain rounding, does not raise on precision loss, and raises for overflow, underflow and division by zero. The class default behavior is replaceable. A custom behavior can return a replacement from `exceptionDuringOperation` for a raised RangeError; returning null leaves the error to propagate. With an exception flag disabled, overflow, underflow or division by zero returns `notANumber`; precision loss rounds. Decimal parsing uses its own default representation behavior, independent of the mutable arithmetic default. Exception callbacks are a JavaScript structural bridge, not Objective-C exception identities.

Bounds are applied before exponent-sized powers can be allocated for extreme exponent text. Arithmetic rounds representable results back into the exponent range; nonzero results below 1e-128 raise or return NaN according to behavior. Error policy, rounding and bounds are documented behavior of this implementation; exact platform-specific NSDecimal internals and all Apple selectors are not claimed.

## Transformer

`NSEValueTransformer` is subclassable, with a process-wide named instance registry. Registration replaces or removes a name; lookup returns the registered instance. `transformedValue` is subclass responsibility. `reverseTransformedValue` rejects non-reversible classes and defaults to the forward transform for reversible classes. Standard boolean negation and nil-check names are exposed through `NSENegateBooleanTransformerName`, `NSEIsNilTransformerName`, and `NSEIsNotNilTransformerName`; both null and undefined bridge nil. Archive transformers and dynamic class lookup by string are unsupported. The object controller now calls `transformedValue`; the closure-based predecessor is gone.

## Hour-cycle follow-up

Style parsing now honors Intl resolved h11 and h24 hour cycles: 0–11 with a day period and 1–24 respectively, with 24 normalized to the same civil day at hour zero. The red/green regression covers midnight and noon in both cycles; [faithful-values-hourcycle-green.log](faithful-values-hourcycle-green.log) records 10 passing date tests.
