# FX fidelity execution plan

The owner-approved specification is `docs/superpowers/reviews/2026-11-08-fx-device-families.md`, supplemented by the owner's instructions in this chat. Work stays on `fix/blind-rewrite-friction` and `prerelease`; no branches, pushes or extra worktrees.

The owner's revised decision is **option A: per-app FX entry modules bound at load time**. Attributed constructors read their own per-app binding and resolve that app's live session when needed, including after native await, in timers and in third-party callbacks. This is cooperative attribution in the shared JavaScript realm. There is no ambient execution context, public client factory, or fallback app selection. Base entries outside application bundles reject construction of attributed classes clearly. Pure classes may be re-exported unchanged. Per-app bindings remain instances of the base class, with one stable binding per app/type.

The ambient contexts, branded records, process authority and NSE bridge from `79fa0ab`, `1e4f90a`, `4722c02`, `5cedae2`, `e94cea2` and `d3255ce` were reverted in `59edf3a`. None is retained. Ambient callback wrapping stays cancelled. The owner has separately approved DispatchFX's in-realm performance core, Tasks 1–6 of the immutable Dispatch plan, after option A. Tasks 7 onwards, worker pools, closure conversion, Tier 2, adoption and App Nap are outside this job. Zlib, CompressionFX, CryptoFX and the guard corrections are preserved.

All four compilation routes are now covered by the owner's stated contract: attributed FX requires the SynCloudOS plugin; non-plugin/base imports remain supported except attributed construction, which fails clearly. Separate SDK copies find no live registry and fail with the family error; no deduplication or provenance checks. App-session ambiguity follows SCOS. Compiled fixture imports are already bound; tests can use the internal binder, without a new test-host API unless necessary.
