## Semantic limits

These implementations are bounded web counterparts, not complete Apple Foundation implementations. The report and guide disclose the six supported numeric date-pattern tokens, Gregorian-only parsing, positive-era patterns, absent milliseconds, fixed missing-field/two-digit-year defaults, and deterministic repeated-wall-time handling. An independent Intl probe across 51 Gregorian locales and four date styles passed 204 midday round trips; this is Node/ICU evidence, not all browser ICU implementations or all dates.

Decimal behavior is explicitly bounded to 38 significant digits and exponents -128 through 127. Handler scale/error policies and the JavaScript exception callback are documented; exact platform-specific NSDecimal internals and every arithmetic selector are not claimed. Transformer archive variants and Objective-C dynamic class lookup are absent by design.

The Foundation undo manager provides explicit synchronous grouping and inverse registration. It does not provide event-loop grouping, asynchronous compensation, poisoned-entry protection, or the complete NSUndoManager selector surface. A throwing handler can leave a partially changed model; the report discloses this and does not claim runtime compensation for raw Foundation history. The runtime adapter retains its stronger transaction/authority behavior.

## StrictMode image-backing follow-up: b00567a

Read-only review found no concrete lifetime or stale-client authority defect in this follow-up. `src/NSE/Controls/Images/NSEImage.tsx:295` permits reuse only for the same physical element and exact layer client with an unaborted connection. A reconnect clears the pending retirement token; a replacement client or disabled backing retires the previous connection synchronously. A real unmount makes retained-handle acquisition return null immediately and releases its existing backing in the queued microtask. The identity check in release prevents an older cleanup from clearing a newer connection. Repeated disposal of an already retired AFXLayer is safe because `AFXLayer.dispose()` is idempotent.

The getter at `NSEImage.tsx:315` reads `connection.layers` and `connection.element`, so a retained handle cannot bind a replacement connection through its original render's client. Independently exercised the actual component in an in-memory esbuild/React/jsdom probe: retained the handle from client A without allocating its layer, replaced A with B and acquired through the retained handle, replaced B with C, flushed old cleanup, disabled/re-enabled backing, and unmounted. All checks passed: only B/C/C were bound, replaced clients aborted immediately, stale cleanup left C live, policy reenabling created fresh backing, and actual unmount denied acquisition before its microtask aborted the backing. The probe used instrumented layer clients; it does not substitute for browser rendering evidence. Its first attempt used the wrong JSX transform and failed before component execution; rerunning with the project's automatic JSX behavior passed.

Reviewed the supplied red/green logs: the StrictMode identity regression fails before the change, and the post-change focused view/image run reports 18 passing tests. No broad suite was rerun. Parent retains the live About/SDK acceptance gate.
