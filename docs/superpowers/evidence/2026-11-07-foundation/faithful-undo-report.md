# Foundation undo extraction

The Foundation manager and the system adapter share `Foundation/internal/UndoHistory`: it owns entry/group storage, registration and coalescing, group close, redo retirement, frontier selection, and replay commit. It contains no runtime identity, responder, DOM, React, partition, or lease types. `createUndoManager` remains the system adapter: it owns runtime identity, responder registry, revocable partition state, reservations, cleanup, restoration, observation, asynchronous replay compensation, refusal classification and poisoning. The mounted AppSDK lease is still the revocable facade; the raw Foundation manager is never handed to an app in its place.

`NSEUndoManager` supports synchronous `registerUndo(target, handler)`, explicit nested groups, `setActionName`, `undoActionName`, `redoActionName`, `undo`, `redo`, `levelsOfUndo` (zero means unlimited), `canUndo`, `canRedo`, `isUndoing`, `isRedoing`, `groupingLevel`, `removeAllActions`, and `removeAllActionsWithTarget`. A handler registers its inverse during replay; replay reverses group order. A returned thenable is rejected and its rejection observed. Groups are explicit: no browser run-loop auto-grouping is claimed. Handler exceptions propagate; the Foundation API does not claim the runtime adapter's asynchronous compensation or poisoned-entry guarantees. Consumers must ensure a throwing handler has not left an inconsistent model before retrying.

`NSEUndoRegistrationCapability<Action, Reservation, Options>` is a structural contract for adapter-provided registration and does not grant owner, registry, clear, disposal, inspection or lease creation authority. NSE value controls and the AppSDK history contract derive from it; runtime and React mounted projections remain limited to their issued lease. Existing runtime action and result contracts remain system types; this change does not turn them into Foundation Cocoa classes.
